QA Smoke Test Deck

This is a stable HTML document used by HTMLRadar's pre-deploy smoke test. The structure is deliberately simple — 5 clearly-titled sections, vertical scroll, no swipe transforms — so we can assert detection works against a known-good baseline.

01 / 05

Section A

Why we test

Real prospects open decks on phones. Real phones do momentum scrolls, swipe gestures, and background tabs. Real browsers cache 410 responses heuristically. Real Cloudflare edges serve stale bundles. None of that shows up in jsdom unit tests.

This deck exists so a Playwright session in a mobile viewport can walk through 5 sections at a known cadence and the smoke test can assert that the dashboard reports back the same shape — total reading time matches the dwell sum, scroll depth crossed at least 80%, every section title is non-meta.

02 / 05

Section B

What "passes" means

The smoke test passes when: (1) the recipient flow shows the deck on mobile without console errors, (2) all 5 sections are detected by title, (3) reading time stays bounded above by tab-open time, (4) max scroll depth crosses 0.5, (5) the hide-viewer button on the owner dashboard reflects state inside two seconds.

Any one of those failing means a regression we shipped today would have stopped at the test gate instead of reaching a real recipient.

03 / 05

Section C

Why this content matters

Section detection in HTMLRadar's tracker relies on visible heading text, font-size hierarchy, and slide-container heuristics. A real-world fixture stresses each one. This deck uses semantic h2 headings, so Strategy 1 (configured selector) should win — the simplest happy path.

If detection ever falls through to Strategy 4 (prose buckets) on this deck, something has regressed in heading discovery — and the smoke test will fail loudly.

04 / 05

Closing

The end of the test deck

If you got here scrolling, the test recipient flow worked. Reading time should be roughly equal to the time the Playwright session dwelled, scroll depth should approach 100%, and the owner dashboard should show one new viewer with five sections read.

If any of that diverges by more than the test tolerances, the smoke test fails and tells you which assertion broke.
